# Shirone IPv4 ingress

Public IPv4 requests for `hyperbola.cc`, `www.hyperbola.cc`, `blog.hyperbola.cc` and `strapi.hyperbola.cc` are accepted by the existing txy HAProxy, selected by TLS SNI and passed as untouched TLS over a restricted SSH reverse tunnel from imini to an independent Higress Gateway. HAProxy sends PROXY v2 over the tunnel so the isolated Gateway records the original client IP. The Gateway terminates TLS and runs the configured Higress WAF in DetectionOnly mode; it is not a blocking WAF. Other SNI names and HTTP traffic continue to use the original txy Traefik backends with their existing PROXY v2 configuration.

The txy host has no IPv6 default route, hence the home-initiated tunnel. This path depends on one txy host, one imini tunnel and one independent Gateway replica; it is not high availability. The existing direct IPv6 site entry remains separate. Neither Traefik's former WAF nor a blocking WAF is implied by the TLS passthrough path.

The dedicated Gateway's ClusterIP is `10.102.238.215:8443`, Service UID `b3713805-dcfc-4bb1-92c9-83e8197c1b21`. It accepts only PROXY v2 connections from imini; its routes permit only the four site/admin hosts and prevent an unrelated Host from being served with an allowed TLS SNI. The NetworkPolicy trusts the imini node IP, including hostNetwork workloads sharing that address; it does not authenticate an individual process. Keep the Service private and revisit this boundary before changing scheduling or networking.

The restricted account uses the existing txy SSH listener, with its own key, a scoped SSH Match block and one loopback reverse port; other SSH users retain their settings. See [TUNNEL.md](TUNNEL.md) for state, verification and guarded removal. The HAProxy apply and rollback playbooks are documented in [EDGE.md](EDGE.md). [isolated-gateway/VALIDATION.md](isolated-gateway/VALIDATION.md) records the security tests and UID-guarded Gateway rollback. Configuration is under the Ansible project's `proposals/shirone-ipv4` and mirrored here; credentials stay in protected host storage, never Git.

On 2026-11-01 the managed tunnel and SNI cutover were applied after the dedicated Gateway tests. External IPv4 requests returned 200 for all three site names and for the admin when resolved to txy; the anonymous draft API returned 404. An unrelated twikoo domain had the same HTTP status before and after reload. Cloudflare DNS now contains a DNS-only A record for `strapi.hyperbola.cc` in addition to its existing AAAA; the reviewed record ID and expected value are stored in `/home/hyperbola/Work/ops/reports/shirone-ipv4-dns-20261101.json`. Some recursive resolvers can retain prior negative answers until their cache expires.

To roll back, first use the guarded HAProxy rollback in `edge-rollback.yml` after reviewing current service state and the impact: this restores the original configuration, whose blog upstream was already unreachable and returned 502. Remove the DNS A record only via `cloudflare-strapi-dns.yml` with the exact saved ID and matching owner/value; never alter the AAAA. Then stop/remove the owned tunnel with `tunnel-rollback.yml`. Remove the dedicated Gateway only after disconnecting external traffic, using `isolated-gateway-rollback.yml` with its exact UID receipt `/home/hyperbola/Work/ops/reports/shirone-ipv4-uids-20261101.json`. Review actual state before any rollback; an interrupted operation or concurrent change requires reconciliation rather than blind retry.

The earlier `relay-nginx.conf.j2`, separate sshd template and associated disposable tests remain historical candidates; the active path uses neither the mTLS HTTP relay nor the separate SSH port. Do not run broad legacy AddOn or infrastructure changes merely to deploy this ingress.
